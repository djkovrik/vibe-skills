# Исправления аудита полноты и восстановления

Пакет 2.1.0, 2026-09-06. Формат AppSpec остаётся 2.0. Основание: аудит от 2026-09-05.

| Пункт аудита | Изменение |
| --- | --- |
| F1: неполный resume | Возвращаются полный активный AC/gate, незавершённые обязательства, блокеры, pending checks, решения, последние активные recovery packets и required reads. `safeToContinue` отделён от `completionEligible`, который вычисляет агрегатор. |
| F2: повторный аудит | Immutable попытки в `.vibe/audits/<request-id>/`, история привязок, восстановление orphan request с исходным ID и digest. Запись request и привязки выполняется под общей блокировкой ledger. |
| F3: старое evidence | UTC-сравнение времён, проверки внутри окна аудита, final после завершения аудита, start/end fingerprints и execution status. Timeout оставляет interrupted receipt; процесс завершается вместе с дочерними процессами. Поздний успешный результат может закрыть предыдущую неудачу. |
| F4: слабый waiver | Accepted decision JSON с точными obligation IDs, причиной, сохранённой цитатой пользователя и hash исходного сообщения; поддерживается supersession. Произвольный исходник или ссылка на Markdown больше не считается решением. |
| F5: потеря решений и текущей работы | Немедленное сохранение steering, immutable checkpoints специалистов, восстановление после compaction внутри turn и при прямом вызове специалиста. `reconcile-spec.py` принимает утверждённую редакцию с архивированием предыдущего ledger и повторным открытием текущих обязательств. |
| F6: декларативные evals | Два свежих Codex CLI процесса работают с настоящим тестовым репозиторием. Проверяются поведение кода, сохранность пользовательского файла и исходных тестов, факт resume по host events, receipt и checkpoint. |
| F7: неполная установка | `-MissingOnly` сохраняет существующие установки; `check-vibe-installation.py` сравнивает все skills из manifest с установленными файлами. |
| Смысловая полнота | Аудит обязан сопоставить каждый раздел нормативных документов с обязательствами или обосновать контекстный характер раздела; есть генератор списка source anchors и проверка полноты таблицы. |
| Изоляция аудитора | Fresh-process launcher фиксирует host thread event, argv, привязку запроса, hashes prompt/events, результат процесса и fingerprints. Самодекларации `implementationContextAvailable: false` недостаточно. |
| Конкурентная запись | OS-owned блокировка охватывает чтение, сравнение digest, изменение и atomic replacement; immutable artifact создаётся атомарно без перезаписи. |
| Контракт Architect | Приведён к общему immutable JSON handoff с assignment/base/result fingerprints. Gate-only assignments также имеют границы и состояние исполнения. |
| Git commits | Зафиксирована стратегия commit перед финальным циклом; новый HEAD требует осознанного reconciliation и повторной проверки, а не изменения старых receipts. |

Рабочие команды и правила находятся в [recovery-contract.md](../vibe-developer/references/recovery-contract.md); установка и release gate — в [INSTALL.md](../INSTALL.md).

Проверены регрессии на не начатую реализацию, потерянные блокеры, failed/missing evidence, повторный аудит, orphan request, waiver с неверной областью/изменённым источником/supersession, изменение спеки, commit drift, конкурентных writers, interrupted/mutating checks, gate-only recovery, контроль source coverage и launch evidence. Сквозной тест проверяет GAPS → исправление → новая попытка PASS → final и отклонение неправильного порядка времени.

Отдельно выполнена независимая проверка двумя агентами без передачи истории и воспроизводимый двухэтапный CLI eval. В обоих случаях восстановлена частичная реализация, пройдена исходная проверка поведения и сохранены пользовательский файл и тесты.

Восстановление проверяется контролируемым отсутствием предыдущей истории. Это не измерение внутренних срабатываний автоматического compaction конкретного хоста. Source coverage и записи решений обеспечивают проверяемую структуру; смысл требований и действительное содержание пользовательского согласования по-прежнему проверяет независимый аудитор. Файловые launch receipts не являются аппаратной аттестацией против намеренной подделки всего репозитория.

Старые receipts без новых полей не доказывают текущую полноту: их следует сохранить и повторить проверки обновлённым runner. Старые audit attempts не перезаписываются. Автоматической миграции Protocol 1.x не добавлено.

Итоговая проверка: полный пакет — `VALIDATION PASSED: 14 skills`; 48 Python-тестов в полном прогоне и дополнительная регрессия сохранения старого receipt при повторной проверке — успешно; installer и Gradle runner — успешно; двухэтапный CLI gate — `STATEFUL AGENT EVALS PASSED`. Всего проверено 49 отдельных Python test cases.

Установлен отсутствовавший `vibe-acceptance-auditor` через Junction. Итоговый installation-health: `healthy: true`, `current: 14`, `total: 14`. Остальные 13 junctions уже использовали обновлённый пакет.
